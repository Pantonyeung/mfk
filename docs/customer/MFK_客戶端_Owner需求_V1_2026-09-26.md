# MFK 客戶端 Owner 需求 V1
版本：V1
日期：2026-09-26
狀態：OWNER CANONICAL / FINAL GAP = 0
範圍：磨飯 Customer PWA / Web

## 1. 文件定位
本文件記錄 Owner 已確認的產品要求、交易邊界、會員規則、Admin 可配置項與不可違反的產品語義。
如 Working V0–V18、早期研究、舊 Handoff 與本文件有衝突，以本文件為準。

客戶端定位：
- Mobile First PWA / Web
- 品牌展示、快速點餐、到店自取、訂單追蹤、回購、會員記憶
- Customer 端不是正式 Order Authority
- 正式 Order、Pricing、Sellability、Coupon Redeem、Payment Verification 最終事實仍由既有 MFK / SMT / canonical authority 負責

## 2. 全局資訊架構
固定底部五導航：
1. 首頁
2. 點單
3. 記憶罐
4. 訂單
5. 會員

記憶罐 = Cart，固定在中央。Header / Bottom Navigation 固定，中間內容垂直 Scroll。

## 3. 啟動頁
- 品牌開場、Logo 組成動畫、磨飯 IP / Mascot
- 動畫不可阻核心資料載入；Reduced Motion / 低效能有簡化版
- 最後只保留兩個 CTA：進入主頁、進入會員頁
- 不設「直接點餐」作啟動頁 CTA
- CTA 文案、排列、主次及 Motion Storyboard 後續 Visual / Motion Brief 再定

## 4. 首頁
固定頂部：Logo + 店舖營業狀態。
首頁是品牌 Storefront，主要內容：
- Hero / 品牌主圖
- 公告
- Top 6 推薦
- 三快捷入口：記憶券 / 常購清單 / 期間限定

「期間限定」為固定入口名；內容可按當期顯示本週限定 / 今期限定飲品 / 季節限定 / 節日限定。

Top 6：
- Admin 管理推薦 Pool
- 新 Session 可換組合，同 Session 穩定
- 同一組不重覆 Product
- Sold Out / Unavailable 自動剔除

非營業時間仍允許 Browse / Product Config / Add to Cart / Edit Cart。
正式 Commit 前重新驗證接單狀態；關店時 Zero Formal Order / Zero Display Number / Cart 不清空。
Scheduled Order 不屬 V1 預設功能。

## 5. 點單頁
每個 Category：
- 1 張 Featured Large Card
- 其餘 Small Cards

大卡 / 細卡只屬 Presentation，不得有不同 Product / Pricing / Sellability Authority。

Product Card：
- 圖片、名稱、價格、Tag、Sold Out、Favorite Heart
- Heart Single Tap；收藏可做短 Heart Burst
- 不使用 Double Tap

Product Detail：
Hero → Combo Upgrade → Required → Optional → Qty → Recommendation → Summary → Add to 記憶罐

Required 未完成不得加入 Cart。

飯團 A/B/C/D 由 Catalog Metadata 定義，不可由 Price 反推。
Single Rice Ball 可升級符合資格的套餐，保留原 Product Identity 和有效選項，只補缺少 Required，再 Re-quote。

## 6. 推薦
推薦只負責 Candidate Generation / Ranking / Presentation。
不可擁有 Product Truth / Pricing / Sellability / Combo Eligibility / Required Validation / Order Authority。
V1 可用 Rules + Semantic Tags + Co-purchase + Session + Member History + Context。
Sold Out / Unavailable / Wrong Window / Invalid Combo / Incompatible 必須 Filter。
Recommendation failure 不阻 Checkout。

## 7. 記憶罐 / Checkout
固定 4 Step：
1. 確認商品
2. 聯絡與取餐
3. 付款
4. 提交 / 確認

Cart Line 支援 Quantity +/-、Edit、Remove、Modifier / Combo Child Summary、Line Total。
某一 Line 失效只修該 Line，不清空整 Cart。

首次交易要求：
- 稱呼
- 電話

電話已知後 Pickup Code = phone last4。

## 8. 三種編號
Pickup Code：
- phone last4
- Human Pickup Verification
- 可在 Formal Order 前存在
- 不是唯一 ID

Display Number：
- SMT / Store 正式 Order 流水號
- Formal Order 後才存在

Fallback Reference：
- WhatsApp / Manual fallback 人工參考碼
- 4–6 位純數字，預設建議 6 位
- 只作人工查詢 / 對單
- 不是 Order ID / Pickup Code

## 9. 付款
付款：Cash / Electronic。

Electronic：
- FPS / PayMe 等方法由 Admin 設
- 每方法有 QR Code
- Customer 可放大 / 儲存 / Screenshot QR
- 付款後 Upload Screenshot

Screenshot 只是 Payment Evidence，不等於 PAYMENT CONFIRMED。
正式 Submit 前 Screenshot 只屬當次 Checkout Session，離開要重新選。
送到 SMT 後 Evidence 隨 Pending Order 給店員核對。
SMT 代處理訂單做人手核對；Customer 不可自行升級成 PAID Truth。

## 10. Coupon
Coupon 由 Admin Reward / Campaign 發出，包含 Name / Benefit / Validity / Scope / Reason / Status。
有效期全由 Admin 設。

Eligible Coupon 可按 Admin Rule 在 Checkout 自動套用 / 預選，但 Customer 必須見到優惠及 Current Total。

Lifecycle：
AVAILABLE → SELECTED/APPLIED_IN_CHECKOUT → Formal Order Commit Success → REDEEMED

Formal Order 未成功，不 Redeem。

WhatsApp 原則：
- WhatsApp 本身不提供 Coupon 選擇 / 使用
- 一般人工單不使用 Coupon，Coupon 保留下一次

Cash / 未付款 fallback：
- 解除 Coupon
- 顯示 Coupon 保留
- 人工單按無券金額重新顯示並讓 Customer 確認

極端已付款 fallback：
如果 Coupon 已套用且 Customer 已按優惠價完成 Electronic Payment，之後 SMT 三次 Submit 失敗：
- Honor 已付款 Quote
- Coupon → MANUAL_FALLBACK_HOLD
- WhatsApp Template 帶 Original Quote / Coupon / Paid Amount / Proof
- Staff 日後正式補 Manual Order：成功 → Redeem；放棄 / 取消 → Release

## 11. Submit to SMT
最多嘗試 3 次，三次屬同一 Checkout Intent / Submission Identity，不是三張 Order。

成功：
→ SMT ACK / Order Created
→ WAITING_STORE_CONFIRMATION

三次都失敗：
→ 原 Submit Path 鎖死
→ WhatsApp Fallback

WhatsApp 後：
- Zero Background Retry
- Zero Delayed Retry
- Zero Reconnect Auto-submit
- 舊 Checkout Intent 不可復活

若可能已送到但無回覆，只做一次必要 Readback：
找到原 Order → 正常成功；找不到 → WhatsApp。

## 12. WhatsApp Fallback
Template 至少可帶：
- 人工參考碼
- 姓名 / 電話
- Pickup Code
- 取餐時間
- Payment Method / Proof Status
- Product / Option / Qty
- Total
- 系統狀態

WhatsApp 是人工救援，不是第二 Order Engine。
不保證每次都形成完整會員消費紀錄；Staff 如能識別會員可回寫 / 關聯。

## 13. 等待店舖確認
正式分兩段：
SUBMITTING → WAITING_STORE_CONFIRMATION → ACCEPTED / PREPARING → READY → COMPLETED
另有 REJECTED / CANCELED。

SMT 已收到後，絕不可因店舖未接單而再次 Submit。

Waiting Screen：
- 訂單已成功送達
- 等待店舖確認
- 動畫、已等待時間、Pickup Code、Order Summary
- 可退出、可查看詳情
- 不可只有無限 Spinner

狀態更新：
Realtime Doorbell → Canonical Readback。
Fallback = Read-only Polling。

以下由 Admin 設，不寫死：
- Auto Refresh Interval
- Manual Refresh Cooldown
- Busy Hint Threshold
- Contact Store Threshold
- SMT Pending Reminder Delay
- Reminder Repeat Interval / Enabled

Refresh 永遠只讀，不重新 Submit。

## 14. 訂單頁
Filter：
- 進行中
- 已完成
- 全部

Order Card：
- Display Number
- Pickup Code
- Primary Status
- Date / Time
- Product Summary
- Total
- Payment Method
- 查看詳情
- 再來一單
- 設為常用訂單

進行中自動更新；完成單是 Read-only Historical Snapshot。

## 15. Favorite / 常用訂單 / Reorder
Favorite Product = 單件 Product 收藏。
常用訂單 = Saved Order Intent / Template，不是舊 Order 本身。

Reorder：
Past Order → Copy Intent → New Cart → Current Revalidation → Repair → Final Review → New Order

禁止重開 Historical Order 或直接用舊 Price。
首頁「常購清單」統一承載：喜愛商品 / 常用訂單。

## 16. 會員模型
首次交易只需稱呼 + 電話，即建立 Ghost / Unactivated Customer Record。
不做 SMS / Email / OTP。

Ghost 可累積 History / Memory Seeds / Coupon / Preference / Favorite / Frequent Signals。
同一裝置可用 Local Membership Token / Session 維持識別。
Phone 是 Contact / Login Identifier，不是 Canonical Customer ID。

後續第 2 / 3 次或適當時機引導正式註冊。
正式註冊可要求 Phone + Password + Optional Profile。
Customer UI 永不顯示 UUID。

正式會員 Login：Phone + Password。
Password 只保存安全 Hash；Staff / Admin 不可查看原密碼。

## 17. 換手機 / 忘記密碼 / 更改電話
不做自動 OTP Account Recovery。

Customer 透過 WhatsApp 聯絡店舖，提供舊電話與已登記資料。
人工核對資料可包括：姓名、舊電話、DOB（如自願提供）、最近 Order / 常買內容、其他 Profile Information。

Admin 核對後：
- 保留同一 Canonical Customer ID
- 舊 Phone 改 New Phone
- 保留 Seeds / Coupon / Favorite / Preference / Order History
- Reset Credential
- 全程 Audit

可向 Customer 顯示：「帳戶資料核對約需 1–2 個工作日。」

Reset Password：
- Admin 只可 Reset，不可查看舊 Password
- 每次產生獨立一次性 Temporary Password
- 不使用全店共用固定預設密碼
- WhatsApp 發送
- 首次登入強制改密碼
- Temporary Password 用後失效 / 過期
- Reset Actor / Time / Reason / Old-New Contact 寫 Audit

## 18. Memory Seeds
Owner 核心規則：
- Lifetime Seeds 永不扣
- Reward Use 不令 Seeds 歸零
- 不在 Submit / Accepted / 即時 Completed 當刻派

派發：
Business Day / 日結完成後批次計算
→ Eligible Completed Orders
→ Seed Rule
→ Seed Ledger Append
→ Reward Milestone Evaluate
→ Coupon Issue

已派 Seed 不刪除。
同一 Milestone 只派一次 Reward，需要 Issuance History / Cursor。

## 19. Admin Reward / Campaign
Admin 可設定：

Audience：
- All Customers
- Visit Count >= N
- Grade / Segment
- Optional Self-declared Profile Fields
- 指定活動對象

Trigger：
- Seeds 達標
- Visit Count
- Anniversary
- 指定日期 / Campaign
- Owner 全客派發

Reward：
- Coupon / Benefit

Validity：
- Start / Expiry / 有效日數 / Usage Scope

全部由 Admin 配置。

## 20. Grade / Profile / Segment
可支援：
- Member Grade
- Visit Count / Repeat Frequency
- Optional Gender
- Optional Birthday / DOB
- Favorite Category
- Spending / Order Habit

Gender / DOB 必須 Optional / Self-declared，不由姓名推斷。
Segment 用於 Experience / Promotion Audience，不改 Order Authority。

## 21. 飲食偏好
可保存：不要青瓜、少飯、常選飲品、常選口味。
如 Product 有 Compatible Formal Option，可自動預選。
如無，不能暗中改 Product，只提示未能自動套用。
所有 Preference 可見、可改，最終仍經 Product / Required / Pricing Validation。
偏好與 Allergy 分開；V1 不把普通 Preference 當 Allergy Safety Engine。

## 22. 記憶分章
Memory Badge 是非金錢型 Achievement。
例：奶茶 / 飯團 / 飯麵 / 限定探索 / 常客。
來源為真實 Order History / Product Category / Behavior。
可顯示 Icon / Title / Copy / Progress / Achieved At / Next Milestone。
Badge 預設不直接等於 Coupon / Discount；如有 Reward，必須經 Admin Reward Rule。

## 23. 會員頁
建議順序：
1. 姓名 / Pickup Code / Memory Seeds
2. Reward / Coupon / Expiry / Next Reward
3. 常買 / 喜愛 / 常用訂單
4. 我的偏好
5. 記憶分章
6. PWA / Notification Onboarding
7. 規則 / 私隱 / 資料聲明

## 24. PWA / Push
會員頁引導：
NOT_INSTALLED → 加到主畫面
INSTALLED_NO_PUSH → 開啟訂單通知
PUSH_ENABLED → 顯示已開啟

高價值通知：
- 店舖已確認
- Delay / ETA
- 可取餐
- Reject / Cancel
- Reward / Coupon Expiry（按 Consent / Policy）

Membership 不等於 Marketing Consent。
Service / Reward / Marketing Notification 概念上分離。

## 25. Admin Config
以下不可寫死：
- Waiting / Refresh / Reminder Timing
- Memory Seed Rule
- Reward Milestone
- Coupon Benefit / Validity
- Campaign Audience / Schedule
- Grade / Segment Rule
- Electronic Payment Methods / QR
- Recommendation Pool
- Featured Product
- Limited Product Window

Customer Frontend 只 consume Published Config。

## 26. 永久邊界
- Customer ID ≠ Phone
- Pickup Code ≠ Display Number
- Fallback Reference ≠ Order ID
- Membership ≠ Marketing Consent
- Payment Screenshot ≠ Paid Truth
- Recommendation ≠ Pricing Authority
- Favorite Product ≠ 常用訂單
- Reorder ≠ Reopen Old Order
- Memory Badge ≠ Money Reward
- Cart / Checkout ≠ Formal Order
- SMT Received ≠ Store Accepted
- Closed Store ≠ App Disabled
- WhatsApp Fallback ≠ Second Order Engine

## 27. V1 延後
- Scheduled / Future Order
- SMS / Email OTP
- Social Login
- Wallet / Stored Value
- Gift Card
- Subscription
- Complex Loyalty Economy
- Advanced AI Recommender
- Enterprise CRM
- Allergy Safety Engine
- 多店跨店會員治理
- WhatsApp 自助 Coupon
- 第二 Payment / Pricing / Order Engine

## 28. Final Acceptance Invariants
1. Retry 不得建立重覆 Order。
2. WhatsApp Fallback 後舊 Online Submit 永久停止。
3. Coupon 未成功交易前不得正式 Redeem。
4. 已付款 Coupon fallback 必須有 Hold / Resolve。
5. Seeds 只在日結後按規則批次派。
6. Seeds 永不因 Reward Use 被扣。
7. Phone 永不作 Canonical Customer ID。
8. 無 OTP 的新裝置不能只憑 Phone 自動取得舊會員私有資料。
9. Password 永不明文保存；Reset 只能發一次性臨時密碼。
10. Reorder 永遠 New Cart + Current Revalidation。
11. Waiting Refresh 永遠只讀，不重新 Submit。
12. 金額 / Sellability / Required / Combo Eligibility 由正式 Authority 決定。
13. Membership / Loyalty / Marketing Consent 分離。
14. Internal UUID / Engineering ID 不顯示 Customer。
15. 裝飾動畫失敗不能阻點餐主流程。
