## Artifact contract

`MFP_ADMIN_SELECTED_BUSINESS_CONFIG_EXTRACT_V1` is labeled “selected business configuration extract,” never a full-system backup.

Required section: `catalog` only, matching the shared canonical envelope. Optional selected sections are `optionCenter`, `logicalPrinters`, `printTemplates`, `printRules`, `printTemplateCatalog` and `printTemplateProfile`. An absent optional section is omitted from `sections` and `inventory`, named in `absentOptionalSections`, and shown in the prepared-download notice. `selectedSections` lists present fields, so both lists together cover the complete selected scope. Present-empty objects/arrays remain present and differ from absence in both the selected checksum and canonical fingerprint. No empty/default data or derived option-center state is synthesized. Missing catalog or malformed-present section shapes stop preparation. Product rows are mandatory; declared catalog/options collections, logical-printer rows and optional print-version/profile rows must have their existing array-of-records shape. Rules for known product/combo IDs must be records, while unknown future rule metadata remains copied. These are shape checks, not full business-validity or referential-integrity validation. Optional `printTemplateCatalog` and singular `printTemplateProfile` are copied only when present with the existing declared schema and collection shape. Their absence is recorded; no data is seeded or inferred. The export is not a validator or migration of individual template versions/renderers.

Unknown fields inside these selected sections are recursively preserved without editor normalization or defaulting. Top-level fields outside the selection, including staff/authentication, customer records and transaction history, are not copied, and their field names are listed in exclusions. Sensitive-looking nested field names or credential-bearing strings stop the entire extract and name the JSON Pointer path without the value. Provider read/identity failures use a fixed error code rather than echoing raw server messages. Nested rejection errors contain only the JSON Pointer path, never field values. There is no silent redaction and no claim that arbitrary opaque strings have been semantically classified. This conservative screening may also stop legitimate ambiguous business extension fields, which require review rather than a bypass.

Metadata records capture time; authenticated-active source kind, endpoint path and actual configured request URL (resolved against the browser document base, just like fetch); envelope schema, store, revision, canonical publish time; **separate** Admin fingerprint and canonical envelope fingerprint; selected/missing-optional section inventory; exclusions; and array/object/collection counts. The canonical fingerprint is checked using the existing FNV-1a32 contract, which is an integrity check rather than a cryptographic signature. A separate SHA-256 checksum covers exactly UTF-8 bytes of compact `JSON.stringify(extract.sections)`. Consumers may parse the artifact and use that exact serialization to recompute it. The file itself uses indented JSON for readability.

The source read is a point-in-time capture. A later publication does not retroactively alter it. A known visible canonical-identity change invalidates the prepared link; pending responses after identity change or unmount are ignored. Duplicate preparation clicks are suppressed. Re-preparation and unmount revoke the local object URL. The user must explicitly activate the download link, and the UI never claims the browser saved or verified the downloaded file.
